结构化总结

整体架构

Server 层 + 存储引擎层
  • Server 层:连接器(连接/鉴权)→ 分析器(词法语法)→ 优化器(索引/执行计划)→ 执行器(调引擎接口)。
  • 存储引擎层:InnoDB(默认,ACID/行锁/MVCC/外键)、MyISAM(早期,不支持事务,表锁)。
  • 客户端-服务端模型,存储引擎可插拔。

InnoDB 内存结构

Buffer Pool + Log Buffer
  • Buffer Pool:最大内存区,以页(16KB)缓存数据/索引页,含 Change Buffer、AHI、锁信息、数据字典。
  • 三大链表:Free(空闲页)、LRU(Young 热 / Old 冷,防全表扫描冲走热数据)、Flush(脏页按变脏时间排序)。
  • Log Buffer:独立缓存 redo 条目,顺序写;刷盘时机:提交(=1)、半满、后台每秒。
  • WAL:先写 redo,改脏页,后台择机刷盘。

索引

B+ 树 · 聚簇 / 二级
  • 聚簇索引(主键):叶子存完整行;二级索引:叶子存 索引列+主键,不覆盖时回表。
  • 最左前缀、覆盖索引(免回表)、索引下推(5.6+ 引擎层提前过滤)、前缀索引(取前缀省空间)。
  • 为何 B+ 树而非 B 树:树矮、磁盘 IO 少、叶子双向链表利于范围查询与排序。

事务与隔离级别

ACID · 在引擎层实现
  • ACID:原子性(undo log)、一致性(约束+锁+undo)、隔离性(锁+MVCC)、持久性(redo log)。
  • 读未提交→脏读;读已提交 RC(每次读建 Read View);可重复读 RR(默认,启动时建 Read View);串行化(读写加锁)。
  • 三类问题:脏读、不可重复读、幻读(RR 部分避免)。

MVCC

多版本并发控制
  • 隐藏字段:DB_TRX_ID(最新事务 ID)+ DB_ROLL_PTR(指向 undo 版本链)。
  • undo log 版本链:更新前写旧版本形成链;Read View 用活跃事务 ID 判断可见性。
  • RR:首次快照读生成后复用;RC:每次快照读都新建。
  • 当前读(update/delete/for update):读最新版本并加行锁/间隙锁/临键锁;insert 产生插入意向锁。

锁

表级 / 行级
  • 表级:表锁(手动整表串行)、元数据锁 MDL(护表结构)、意向锁 IS/IX(行锁前声明)、自增锁 AUTO-INC。
  • 行级(InnoDB):行锁 S/X + 三算法(行锁/间隙锁/临键锁)、插入意向锁(INSERT 排队信号)。
  • 死锁:并发事务互相等待锁资源的循环等待现象。

三大日志

redo / undo / binlog
  • redo log(引擎层,物理逻辑):记"某页偏移做了某修改",支撑 WAL、循环写、保证持久性。
  • undo log(引擎层,逻辑):记行旧版本,用于回滚 + MVCC 版本链,保证原子性/一致性。
  • binlog(Server 层,逻辑):记 SQL/行变化,用于主从复制与时间点恢复。

两阶段提交

redo 与 binlog 一致性
  • prepare:写 redo log 并标记 prepare。
  • 写 binlog:变更写入 binlog。
  • commit:redo log 标记 commit,事务完成。
  • 崩溃恢复:redo 为 prepare 且 binlog 完整则提交,否则回滚。
