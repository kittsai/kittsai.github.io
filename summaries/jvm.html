JVM 组成结构

类加载器把字节码加载进内存;运行时数据区管理内存;执行引擎把字节码翻译成机器指令;JNI 与本地方法库支撑对 C/C++ 的调用。

类加载器

加载 → 验证 → 准备 → 解析 → 初始化
  • 三层:Bootstrap → Extension → Application
  • 双亲委派:逐级向上委派,父加载不了子才加载
  • 目的:安全(核心类不被篡改)、唯一(避免重复加载)
  • 打破方式:自定义加载器 / 线程上下文加载器 getContextClassLoader()

运行时数据区

共享区 + 线程私有区
  • 共享 线程共享:堆、方法区
  • 私有 线程私有:虚拟机栈、本地方法栈、程序计数器
  • 规定数据放哪、谁共享、何时创建销毁

执行引擎

解释器 + JIT + 垃圾回收器
  • 把字节码翻译成机器指令并运行
  • 混合模式:解释器预热/兜底,JIT 加速热点
  • 分层编译:C1 快速预热 → C2 激进优化

运行时数据区 · 五块内存

堆 共享

最大内存 · 对象实例
  • 分代:新生代(Eden:S0:S1 = 8:1:1)+ 老年代
  • 对象熬过 Minor GC,GC 年龄 +1,达 15 晋升老年代
  • TLAB:线程本地分配缓冲,Eden 内每线程独享空间
  • 新生代用标记-复制;老年代用标记-整理/清除

方法区 共享

类元数据 · 常量池 · 静态变量
  • 存类元数据、运行时常量池、静态变量、JIT 代码缓存
  • JDK1.7 永久代(易 OOM)→ JDK1.8 元空间(本地内存)
  • 1.7 起字符串常量池、静态变量移到堆中

虚拟机栈 私有

栈帧 · 方法调用
  • 每方法一栈帧:局部变量表、操作数栈、动态链接、返回地址
  • 递归过深 → StackOverflowError
  • 无法申请内存 → OutOfMemoryError

程序计数器 私有

字节码行号指示器
  • 记录当前线程执行的字节码地址(Native 方法时为空)
  • 作用:流程控制、线程恢复、异常处理
  • 唯一不会 OOM 的区域

本地方法栈 私有

Native 方法服务
  • 为 Native 方法提供栈环境
  • 通过 JNI 调用 C/C++ 实现的函数

执行引擎 · 解释 + 编译混合

解释器 vs JIT

同声传译 vs 文字稿
  • 解释器:逐条翻译执行,负责预热与兜底
  • JIT:热点代码一次性编译为机器码,后续直接运行
  • 这正是"Java 编译与解释共存"的原因

热点探测

HotSpot 计数器
  • 方法调用计数器 + 回边计数器(循环)
  • 热点循环触发 OSR(栈上替换)
  • 计数器半衰减"降温",只留高频热点

分层编译

C1 → C2
  • C1:编译快、质量中等,适合短任务
  • C2:激进优化(逃逸分析、方法内联),适合长跑服务

垃圾回收 · 寻找 / 算法 / 收集器

核心矛盾是 STW(Stop-The-World):不能在变化的对象图上找垃圾,GC 进化史就是让 STW 更短更可控。

寻找垃圾

可达性分析(Java 采用)
  • 引用计数法:循环引用无法回收,Java 不用
  • 可达性分析:从 GC Roots 沿引用链搜索,不可达即可回收
  • GC Roots:栈局部变量、静态变量、常量、JNI 引用、同步锁对象

四种引用

引用强度等级
  • 强:永不回收(普通引用)
  • 软 SoftReference:内存不足时回收(缓存)
  • 弱 WeakReference:下次 GC 必回收(ThreadLocal)
  • 虚 PhantomReference:仅回收通知(堆外内存)

回收算法

三种基本算法
  • 标记-清除:有内存碎片
  • 标记-复制:无碎片但浪费空间(新生代)
  • 标记-整理:存活对象向一端移动(老年代)

常见垃圾回收器

收集器区域算法线程核心目标
Serial新生代标记-复制单线程简单高效,Client 首选
ParNew新生代标记-复制多线程Serial 多线程版,配 CMS
Parallel Scavenge新生代标记-复制多线程吞吐量优先
Serial Old老年代标记-整理单线程配 Serial,CMS 后备
Parallel Old老年代标记-整理多线程配 Parallel Scavenge
CMS老年代标记-清除多线程最短停顿(JDK14 移除)
G1全堆复制+整理多线程可预测停顿(JDK9 默认)

CMS

标记-清除 · 三色标记
  • 五阶段:初始标记STW → 并发标记 → 并发预清理 → 重新标记STW → 并发清除
  • 三色:白(可回收)/灰(待扫子引用)/黑(扫描完毕)
  • 写屏障 + 卡表记录并发期引用变化(脏页 = 位图标 1)

G1

Garbage-First · Region 化
  • 堆分 ~2048 个 Region(1-32MB),角色:Eden/Survivor/Old/Humongous
  • SATB 快照 + 写前屏障;RSet 记录跨 Region 引用
  • Mixed GC:老年代占用达 45% 触发并发标记周期
  • -XX:MaxGCPauseMillis 设定目标停顿

高频问答

为什么说 Java 是解释和编译并存?
Java 同时用解释执行与 JIT 编译,是性能平衡策略。解释器逐行翻译字节码并立即执行、不保存结果(同声传译);编译器对热点代码一次性完整翻译并保存复用(文字稿)。两者结合兼顾启动速度与执行效率。
Java 如何识别热点代码?
HotSpot 基于计数器做热点探测:方法调用计数器统计方法被调次数,回边计数器统计循环体执行次数;热点循环触发 OSR(栈上替换)把解释执行的循环换成机器码。计数器会随时间半衰减降温,只保留高频热点。
CMS 与 G1 的关键区别?
CMS 只管老年代、用标记-清除(有碎片)、追求最短停顿,JDK14 已移除;G1 管整个堆、Region 化、复制+整理(无碎片)、可设定目标停顿时间,JDK9 起为默认。CMS 用写屏障+卡表修正漏标,G1 用 SATB 快照+RSet 缩小扫描范围。
为什么程序计数器不会 OOM?
程序计数器只存一个字节码行号(很小的固定空间),且生命周期随线程,不随对象分配增长,因此是 JVM 规范中唯一不会抛出 OutOfMemoryError 的区域。
