结构化总结

并发三大特性

原子性 · 可见性 · 有序性
  • 原子性：一组操作要么全做完且中途不被打断，要么都不做。
  • 可见性：一个线程对共享变量的修改，其他线程能立刻看到。
  • 有序性：程序按代码书写顺序执行（编译器/处理器会重排序破坏它）。

Java 内存模型 (JMM)

抽象规范 · 主内存 / 工作内存
  • 定义多线程下共享变量的访问规则，分主内存（共享，正式值）与工作内存（线程私有，变量副本）。
  • 解决可见性：强制刷新/失效协议（volatile、synchronized、final）。
  • 解决有序性：定义 Happens-Before 原则，规定哪些操作不可重排。
  • 基本原子性：除 long/double 外的单次读写原子；复合操作需加锁。
  • 落地方式：JIT 插入内存屏障（LoadLoad / StoreStore / LoadStore / StoreLoad）+ 硬件 lock 指令（MESI 缓存一致性）。

三个关键字

volatile · synchronized · final
  • volatile：最轻量同步。保证可见性 + 有序性，不保证原子性。写前 StoreStore / 写后 StoreLoad，读后 LoadLoad+LoadStore。
  • synchronized：较重，三性全保证。靠 monitorenter/exit + 对象头 Mark Word + ObjectMonitor。锁升级：无锁→偏向锁→轻量级锁→重量级锁。
  • final：解决不可变对象的安全发布。构造期 this 不逸出时，构造末尾插入 StoreStore 屏障保证 final 字段对其他线程可见。

AQS 与并发工具

AbstractQueuedSynchronizer
  • 基于 FIFO 双向队列 + volatile state 的框架，用模板方法封装排队/阻塞/唤醒（LockSupport.park/unpark）。
  • 独占模式：同一时刻仅一个线程，典型 ReentrantLock。
  • 共享模式：多线程同时获取，典型 Semaphore、CountDownLatch。
  • Node 的 waitStatus：SIGNAL(-1) 需唤醒后继；CANCELLED(1) 已取消。

ThreadLocal

线程级隔离
  • 每个 Thread 持有一个 ThreadLocalMap，key 为 ThreadLocal（弱引用），value 为存储值。
  • key 用弱引用，便于 ThreadLocal 失去外部引用后被 GC 回收。
  • 但 value 仍被强引用 → 必须 remove() 清理，防止内存泄漏。

线程池

ThreadPoolExecutor · 池化技术
  • 为何用：降低创建/销毁开销、提高响应速度、便于管理监控。
  • 7 参数：核心数、最大数、keepAlive、单位、等待队列、线程工厂、拒绝策略。
  • 执行流程：核心线程 → 队列 → 非核心线程 → 拒绝策略。
  • 拒绝策略：Abort（默认抛异常）、CallerRuns、Discard、DiscardOldest。
  • 最佳实践：阿里规约禁用 Executors（OOM/资源耗尽风险）；CPU 密集 = 核心数+1，IO 密集 ≈ 核心数×2。

线程生命周期

6 种状态
  • NEW 新建 → RUNNABLE 可运行（含就绪+运行）。
  • BLOCKED 等待 synchronized 锁。
  • WAITING 无限等待（park/wait/join）；TIMED_WAITING 限时等待。
  • TERMINATED 执行完毕或异常退出。
