结构化总结

Redis 是什么 · 为什么快

内存 · 单线程 · IO 多路复用
  • 基于内存、单线程驱动、可持久化的数据结构服务器。
  • 完全基于内存:无磁盘 IO 瓶颈,读写纳秒级。
  • 单线程执行命令:无上下文切换/锁竞争;瓶颈在网络 IO 而非 CPU。6.0 后多线程优化网络 IO,命令仍单线程。
  • IO 多路复用:单线程一次系统调用监控多个 fd,就绪才处理,不阻塞。

数据结构

7 种核心类型
  • String(SDS):缓存对象、计数器、分布式锁。SDS 二进制安全、O(1) 取长、预分配、防溢出。
  • List(双向链表):消息队列、最新列表、时间线。
  • Hash:用户属性、购物车;Set(无序不重复):标签、共同好友、抽奖去重。
  • Sorted Set(按 score 排序):排行榜、延迟队列;Bitmaps:签到;HyperLogLog:基数统计。

过期与淘汰策略

Expire + Eviction
  • 过期删除:惰性删除(访问时检查)+ 定期删除(定时随机抽查)。
  • 淘汰策略(内存满时):noeviction 拒写。
  • LRU/LFU/TTL/random × allkeys(所有 key)/volatile(仅设过期的 key)组合。
  • 如 allkeys-lru、volatile-lfu、volatile-ttl(最接近过期)。

持久化

RDB · AOF · 混合
  • RDB:定时快照,二进制紧凑、恢复快;可能丢最后一次快照后的数据。fork 子进程写页缓存再 fsync。
  • AOF:顺序追加写命令,重放恢复。刷盘:always(每条,主线程)、everysec(每秒,后台)、no(OS 定)。
  • 混合持久化:AOF 重写时,文件头用 RDB 全量,之后 AOF 追加。

缓存三大问题

雪崩 · 穿透 · 击穿
  • 雪崩:大量缓存同时失效/宕机 → 打满 DB。解:过期加随机值、多级缓存、限流降级。
  • 穿透:查缓存与 DB 都不存在的数据。解:缓存空结果、布隆过滤器、参数校验。
  • 击穿:单个热点数据过期瞬间被并发击中。解:热点永不过期、提前更新、互斥锁。

集群

主从 · 哨兵 · 集群
  • 主从复制:读写分离,无分片/无故障转移,适合少量读扩展。
  • 哨兵模式:监控+故障通知+自动故障转移(从从节点选主),适合中小规模高可用。
  • 集群模式:水平扩展、自动分片(默认 16384 个 Slot)、无中心,适合大规模分布式。

事务

MULTI / EXEC · 不回滚
  • 一次性、顺序性、排他性执行多命令。
  • MULTI 开启、EXEC 执行、DISCARD 取消、WATCH 乐观锁(键被改则中断)。
  • 本质=命令批处理 + 执行期隔离,但不回滚;基本被 Lua 脚本替代。

常见使用场景

微服务中的 Redis
  • 缓存:加速查询、扛读流量;分布式锁:Redisson 解超卖/重复执行。
  • 排行榜/计数器:Sorted Set 实时排名、String 原子计数。
  • 轻量消息队列:List 简单队列、Stream 可靠消费;特征存储:AI 向量/画像标签。
