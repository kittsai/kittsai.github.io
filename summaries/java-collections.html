Collection · 单列集合（继承自 Iterable，存储一组元素）

ArrayList

List · 动态数组 · 有序可重复
  • 查询快 O(1)：内存连续，按索引计算地址
  • 尾部写入均摊 O(1)，首部/中部写入 O(n)（需移动元素）
  • 扩容：首次 add 扩到 10，满后扩为 1.5 倍
  • 线程安全：否 · 适合查多写少

LinkedList

List · 双向链表 · 有序可重复
  • 写入快 O(1)：前驱/后继指针关联，无需移动
  • 查询慢：需遍历链表逐个查找
  • 内存占用高于 ArrayList（额外存两个指针）
  • 线程安全：否 · 适合增删多查询少

Vector

List · 动态数组 · 有序可重复
  • 所有方法加 synchronized 保证线程安全
  • 扩容为 2 倍（ArrayList 为 1.5 倍）
  • 性能低于 ArrayList
  • 线程安全：是

HashSet

Set · 基于 HashMap · 无序不重复
  • 以 HashMap 的 key 存数据，value 为固定 Object
  • 无序
  • 线程安全：否

LinkedHashSet

Set · 继承 HashSet / 基于 LinkedHashMap
  • 按插入顺序排序
  • 内存占用高于 HashSet（维护双向链表）
  • 线程安全：否

TreeSet

Set · 基于 TreeMap / 红黑树
  • 有序、唯一
  • 底层为红黑树
  • 线程安全：否

Queue

队列 · 通常 FIFO
  • 先进先出，亦有优先级 / 双端变体
  • 多数非线程安全；BlockingQueue 线程安全

Map · 双列集合（存储键值对，键唯一，由 equals + hashCode 判定）

HashMap

数组 + 链表 + 红黑树
  • JDK1.7：数组+链表 O(n)；JDK1.8：+红黑树 O(logn)
  • 允许 1 个 null 键、多个 null 值
  • 哈希：(h=key.hashCode())^(h>>>16)，再 hash&(n-1) 定桶
  • 扩容：负载因子 0.75，首次 put 扩到 16，满后 2 倍
  • 树化：链长 > 8 且容量 ≥ 64 转红黑树；节点 < 6 退化为链表
  • 线程安全：否

LinkedHashMap

数组 + 双向链表 + 红黑树
  • 基于 HashMap，增加双向链表维护顺序
  • 线程安全：否

TreeMap

红黑树
  • 键有序
  • 线程安全：否

ConcurrentHashMap

线程安全 · 高性能
  • JDK1.7：Segment 数组 + HashEntry 链表，分段锁（ReentrantLock）
  • JDK1.8：Node 数组+链表+红黑树，CAS + synchronized
  • 空桶 CAS 插入；非空桶锁住头节点
  • 多线程协作扩容，迁移完标记 ForwardingNode，读无锁路由
  • 线程安全：是

为什么用红黑树而不是平衡二叉树（AVL）？
AVL 严格平衡、查询略优，但插删旋转次数更多。HashMap 中插入与查找都频繁，红黑树以少量查询性能换取更少旋转、更好的插删效率，整体成本更低；且其实现在大规模并发库中更通用，维护成本可控。

HashMap 在 JDK1.7 为什么会发生死循环？
1.7 采用头插法，扩容时遍历桶内链表插入新链表会导致链表反转，并发下可能形成环形链表：
  • 扩容前：A→B→null
  • 线程 t1 记录 A.next=B 后暂停
  • 线程 t2 完成扩容：B→A→null
  • 线程 t1 继续：A→B→A→null，形成环
